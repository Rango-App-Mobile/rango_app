# Posicionamento

> A preencher na Sprint 2 (issue **E5-S2**). Base: benchmark e diferenciais em [contexto.md §2–3](../contexto.md#2-benchmark).

## Problema em uma frase

Decidir **o que** comer é a parte mais difícil de pedir comida, e piora em grupo.

## Persona principal

| Campo | Resposta |
|---|---|
| Nome fictício / idade | |
| Rotina com comida | |
| Quando trava na decisão | |
| Apps que usa hoje | |
| O que faria ela instalar o Rango | |

## Proposta de valor

> Rascunho: *"Do 'não sei o que comer' ao restaurante certo em poucos swipes."*

## Mensagens-chave vs. concorrentes

| Contra | Mensagem |
|---|---|
| Apps de delivery | Eles resolvem **onde** pedir; o Rango resolve **o que** pedir antes. |
| WhatToEat / imdecisive | O Rango não para no "quero isso": mostra restaurantes reais perto de você. |
| BiteSwipe / Food Swipe | O Rango descobre primeiro o que você quer, depois o lugar. |
| Todos | Feito para o Brasil, sem cadastro. |

## Validação

Hipóteses a testar na pesquisa da Sprint 4 (E5-S7):
- [ ] Pessoas travam mais na decisão do "o quê" do que no "onde".
- [ ] Uma sessão de até 6 swipes é aceitável.
- [ ] Recomendar restaurante no mesmo fluxo é o que faz alguém voltar ao app.
